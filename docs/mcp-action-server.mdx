EffiLink hosts a remote [Model Context Protocol](https://modelcontextprotocol.io) (MCP) server at `https://api.effilink.co/mcp`. Once an AI client or agent connects to it with your API key, it can send transactional emails for you, without you writing each API request by hand.

<Warning>
  This server performs **real, authenticated actions on your account**, including sending real emails that use your credits. Connect it only to clients and agents you trust, and keep your API key as private as you would in any backend service.
</Warning>

## Quick reference

|  |  |
| --- | --- |
| **Server URL** | `https://api.effilink.co/mcp` |
| **Transport** | HTTP (remote server, nothing to install or host) |
| **Authentication** | Your EffiLink API key in the `ApiKey` request header |
| **Scope** | Transactional Email API |
| **Sandbox mode** | Supported |
| **Read-only documentation search** | Use the [MCP Query Server](/docs/mcp-server) instead |

## Before you start

<Steps>
  <Step title="Get your API key">
    Create an API key in your EffiLink account settings. See [API Keys](/docs/api-keys) for details.
  </Step>
  <Step title="Configure your sender">
    Set up your sending domain and sender before sending emails. See [how to set up your senders](/api/senders) for instructions.
  </Step>
</Steps>

## Connect a client

The server authenticates every connection with the `ApiKey` header, the same header the REST API uses. Your client must be able to send a custom header when it connects.

<Tabs>
  <Tab title="Claude Code">
    Run this command in your terminal:

    ```bash
    claude mcp add --transport http effilink https://api.effilink.co/mcp \
      --header "ApiKey: your_api_key_here"
    ```
  </Tab>
  <Tab title="Cursor">
    Add the server to your MCP config (usually `~/.cursor/mcp.json` or via **Settings → MCP**):

    ```json
    {
      "mcpServers": {
        "effilink": {
          "url": "https://api.effilink.co/mcp",
          "headers": {
            "ApiKey": "your_api_key_here"
          }
        }
      }
    }
    ```
  </Tab>
  <Tab title="Other MCP clients">
    Any client that supports remote HTTP MCP servers **and lets you set a custom request header** can connect. Use the server URL above and add the header `ApiKey: your_api_key_here`. Clients that cannot send custom headers, such as some web-based connector screens, cannot connect with an API key.
  </Tab>
</Tabs>

<Tip>
  Replace `your_api_key_here` with your own key. Avoid committing config files that contain your key to source control.
</Tip>

## What it can do

The server currently provides one tool:

- **Send a transactional email.** Sends an email to a recipient through the [Transactional Email API](/api/transactional-send). See [Transactional Email](/docs/transactional-email) for the fields it accepts.

After connecting, the client reads the list of available tools from the server, so it always sees the current tool names and input schemas.

<Info>
  More tools will be added over time. This page will be updated as they become available.
</Info>

The tool follows the same rules as the matching REST API endpoint, so the request fields, limits and error codes in the API reference apply.

## Example prompts

Once connected, you can ask your AI client things like:

- "Send a password reset email to [jane@example.com](mailto:jane@example.com) using our reset template."
- "Send an order confirmation to [order-123@example.com](mailto:order-123@example.com) in sandbox mode."
- "Send a welcome email to our new user, then show me the request you used."

## Safety and testing

- **Real emails are sent.** Unless a request uses sandbox mode, the server sends actual email and uses your credits.
- **Test first.** The server supports sandbox mode, which validates a request without sending anything. See [Sandbox Mode](/docs/sandbox-mode), and ask your agent to use it for a first trial.
- **Control what the agent can do.** Many clients let you approve each tool call. Keep that on until you trust the workflow.
- **Rotate a leaked key.** If your API key is exposed, replace it in your account settings and update your client config.

## Limitations

- **Sending only, for now.** Batch sending, delivery reports, campaigns, SMS, contacts, senders and webhook settings are not available through this server yet. Use the [REST API](/api/transactional-send) for those.
- **Verified sender required.** `senderMail` must be registered and verified in your account, or the request is rejected.
- **Same limits as the API.** The server follows EffiLink's own rate limits and credit rules. See [Limits & Quotas](/docs/rate-limits).
